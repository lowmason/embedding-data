Assuming you mean **U.S. NAICS and U.S. SOC**, the strongest public starting points I found are **OSHA’s establishment submissions for NAICS** and **DOL’s SeasonalJobs records for SOC**. Both have documented reporting or coding processes, and both provide descriptions alongside codes. Their versioning rules need careful handling. [osha.gov](https://www.osha.gov/sites/default/files/summary_data_dictionary.pdf?utm_source=chatgpt.com)

I have separated the findings into:

- **Public sources of descriptions of actual establishments or jobs.**
- **Conditional sources**, where the unit, coding provenance, or original classification edition still needs verification.
- **Sources available by request** and **official category descriptions**, which may also suit your purpose.

The distinction I would preserve throughout is **the edition used to assign the code**, versus **a later edition in which that same code happens to remain valid**.

## 1. Establishment descriptions mapped to NAICS

### A. OSHA Injury Tracking Application: Form 300A summary data

**Assessment: The best public bulk starting point for establishment records, with qualifications about description quality and original code edition.**

**Access:** [Annual ITA downloads](https://www.osha.gov/itadata), [summary data dictionary](https://www.osha.gov/sites/default/files/summary_data_dictionary.pdf), and [data users guide](https://www.osha.gov/sites/default/files/ITA_data_users_guide.pdf).

The published schema includes:

| Field | Relevance |
|---|---|
| `establishment_name`, `establishment_ID` | Identifies the establishment |
| `industry_description` | Industry description associated with that establishment |
| `naics_code` | Reported NAICS code |
| `naics_year` | Classification-version information, subject to the qualification below |
| `created_timestamp` | Submission date and time |
| `year_filing_for` | Year covered by the injury report |

These fields are documented in OSHA’s data dictionary. [osha.gov](https://www.osha.gov/sites/default/files/summary_data_dictionary.pdf?utm_source=chatgpt.com)

**Who supplies the mapping?** OSHA describes the NAICS code as reported by the establishment. Its users guide says that submitted values generally remain as submitted, including inaccurate NAICS codes. This supports an employer-reported classification, rather than a NAICS label generated by OSHA’s occupational autocoder. [osha.gov](https://www.osha.gov/sites/default/files/ITA_data_users_guide.pdf?utm_source=chatgpt.com)

**Which NAICS edition?** Earlier submissions used NAICS 2012; data collected in 2023 and later can use **2012, 2017, or 2022**. However, when a code is unchanged across editions, OSHA puts the **most recent applicable year** in `naics_year`. Consequently, that field does **not always establish which edition the establishment originally consulted**. [osha.gov](https://www.osha.gov/sites/default/files/summary_data_dictionary.pdf?utm_source=chatgpt.com)

**Description limitation:** OSHA explicitly notes that the industry description is often a standard NAICS index title. Some records therefore contain little independent information about the establishment’s activities. If you need independently written descriptions, retain substantive descriptions and flag entries that merely repeat taxonomy wording. [osha.gov](https://www.osha.gov/sites/default/files/ITA_data_users_guide.pdf?utm_source=chatgpt.com)

**How I would use it:** Accept records whose original edition follows from the collection rules or additional record evidence. Treat “latest edition in which the code is valid” as a separate metadata concept. Also distinguish the submission year from the injury-reporting year.

### B. EPA Toxics Release Inventory: reported NAICS codes and facility narratives

**Assessment: Strong evidence for reported codes and their edition; the suitability of the description depends on how much facility context you need.**

**Access:** [TRI Basic Plus annual bulk files](https://www.epa.gov/toxics-release-inventory-tri-program/tri-basic-plus-data-files-calendar-years-1987-present).

The relevant components include:

- **File Type 5:** Additional information about source reduction, recycling, and pollution-control activities.
- **File Type 6:** Miscellaneous facility comments, including actual comment text, together with facility identifiers and NAICS information. [File Type 5.docx](https://www.epa.gov/system/files/documents/2024-09/file_type_5_1.pdf?utm_source=chatgpt.com)

**Who supplies the mapping?** EPA’s reporting instructions direct the filer to enter the facility’s primary six-digit NAICS code. A senior official with management responsibility certifies the submission’s accuracy and completeness. This establishes a facility-reporting process for the classification. [epa.gov](https://www.epa.gov/system/files/documents/2026-04/ry_2025_rfi_final_3.24.26.pdf?utm_source=chatgpt.com)

A particularly useful provenance field is **`NAICS ORIGIN`**:

| Value | Meaning | Treatment for your requirement |
|---|---|---|
| `R` | Reported | Candidate for inclusion |
| `A` | Assigned | Exclude unless separately documented as an acceptable human assignment |

EPA documents historical NAICS assignments using crosswalks and other information sources. Filtering on reported origin avoids treating those derived codes as original facility-reported labels. [File Type 6.docx](https://www.epa.gov/system/files/documents/2024-09/file_type_6_1.pdf?utm_source=chatgpt.com)

**Which NAICS edition?**

| TRI reporting year | NAICS edition |
|---|---|
| 2017–2021 | NAICS 2017 |
| 2022 onward | NAICS 2022 |

EPA identifies reporting year 2017 as the first year using NAICS 2017, and reporting year 2022 as the first using NAICS 2022. The reporting year is distinct from the following year in which the form is due. [US EPA](https://www.epa.gov/toxics-release-inventory-tri-program/adoption-2017-north-american-industry-classification-system?utm_source=chatgpt.com)

**Description limitation:** The free text can describe a chemical-use activity, production process, or pollution-prevention project. A facility’s primary NAICS code is not necessarily a suitable classification for that isolated activity. I would retain facility context and inspect whether the narrative actually describes the establishment’s business.

**How I would use it:** Select `NAICS ORIGIN = R`, retain the reporting year, use the edition rules above, and keep actual facility-entered narrative text. This is a useful specialized source, particularly when industrial-process descriptions meet your needs.

### C. Washington State OMWBE certified-business directory

**Assessment: Particularly clear evidence of human classification, but it is generally a business-level source and historical edition evidence is incomplete.**

**Access:** [OMWBE’s explanation of NAICS codes and business descriptions](https://omwbe.wa.gov/certification/frequently-asked-questions-faqs-and-fact-sheets/north-american-industry-classification-system-naics-codes-and-business-descriptions) and its [business-resource directory links](https://omwbe.wa.gov/omwbe-business-resources).

The documented workflow is unusually relevant:

1. The applicant writes a business description and requests NAICS codes.
2. OMWBE assigns codes using the description and supporting evidence, including licenses, training, résumés, invoices, and contracts.
3. A certification analyst helps finalize the description.
4. The approved description and assigned codes appear in the certified-business directory.

Current guidance points applicants to **NAICS 2022**. This is strong documentation of knowledgeable human involvement. [omwbe.wa.gov](https://omwbe.wa.gov/certification/frequently-asked-questions-faqs-and-fact-sheets/north-american-industry-classification-system-naics-codes-and-business-descriptions?utm_source=chatgpt.com)

**Remaining qualifications:** I did not establish the native classification edition of every historical directory record. Also, the record describes a certified business and its capabilities, which may cover multiple establishments or activities.

**How I would use it:** Pursue this for richer business descriptions with analyst-assigned labels, while requesting the assignment or recertification date and the edition used. I would keep it conditional for a strictly establishment-level dataset.

### D. SBA Small Business Search, using SAM registration data

**Assessment: Useful business capability narratives with registrant-selected codes; conditional for strict establishment-level and original-edition requirements.**

**Access:** [SBA Small Business Search](https://search.certifications.sba.gov/advanced), formerly Dynamic Small Business Search.

SAM’s documentation says that Small Business Search combines SAM entity data with supplemental information supplied by small businesses to describe their entities. GSA’s registration guidance directs businesses to select NAICS codes that accurately describe their products or services. These sources support business-supplied narratives and registrant-selected classifications. [SAM.gov](https://sam.gov/about/external-resources?utm_source=chatgpt.com)

For a concrete example, the public [BG Consulting profile](https://search.certifications.sba.gov/profile/JJU3WFH9A515/6V8N3) contains a capability narrative, primary NAICS **541611**, and additional NAICS codes. This confirms that narrative and code fields coexist in actual profiles. [SBA Small Business Search](https://search.certifications.sba.gov/profile/JJU3WFH9A515/6V8N3?utm_source=chatgpt.com)

**Which NAICS edition?** SAM implemented NAICS 2022 on **October 27, 2022**. GSA notified affected active entities that they needed to update their registrations. That establishes the platform transition, but does not prove that every code in a migrated profile was individually reselected by a person under the new edition. [content.govdelivery.com](https://content.govdelivery.com/accounts/USGSA/bulletins/3347f4d?utm_source=chatgpt.com)

**How I would use it:** Preserve the primary/additional-code distinction and obtain evidence of the relevant registration or code-selection event. A recent profile-update date alone is insufficient. Also, do not interpret a broad company narrative with several capability codes as several independent establishment descriptions.

## 2. Occupation or job descriptions mapped to SOC

### A. DOL SeasonalJobs: H-2B job opportunities

**Assessment: The strongest public source I found for detailed descriptions of actual jobs with documented agency classification.**

**Access:** [SeasonalJobs](https://seasonaljobs.dol.gov/) and its [data feeds](https://seasonaljobs.dol.gov/feeds).

**Who supplies the description and code?** DOL documents this sequence:

1. The employer provides detailed duties in a prevailing-wage application, Form ETA-9141.
2. The National Prevailing Wage Center reviews those duties against occupational definitions and tasks.
3. The NPWC issues the SOC classification.
4. The subsequent H-2B application and job order must contain the same duties; application instructions require the code issued on the prevailing-wage determination. [dol.gov](https://www.dol.gov/sites/dolgov/files/WHD/fab/2022-3.pdf?utm_source=chatgpt.com)

Thus, the duties are employer-reported and the final classification is agency-assigned following review.

The [H-2B feed dictionary](https://api.seasonaljobs.dol.gov/sites/default/files/2023-08/H2BMapping.xlsx) identifies useful fields including:

| Field | Use |
|---|---|
| `jobDuties` | Detailed work description |
| `tempneedSoc`, `tempneedSocTitle` | Published occupational code and title |
| `tempneedJobtitle` | Employer’s job title |
| `caseNumber` | Application identifier |
| `jobPwdNumber` | Link to the prevailing-wage determination |
| `tempneedStart`, `tempneedEnd` | Intended employment period |

**Which SOC edition?** DOL’s transition notice establishes **SOC 2018 for prevailing-wage determinations issued on July 1, 2022, or later**. However, some H-2B applications could continue to carry SOC 2010 from an older linked determination. Therefore, use the underlying PWD and its issuance date; do not assign the edition solely from a job-posting date. [flag.dol.gov](https://flag.dol.gov/index.php/node/23042?utm_source=chatgpt.com)

For example, this [Sugarloaf Mountain Hotel housekeeper job](https://seasonaljobs.dol.gov/jobs/H-400-25216-217864) publishes substantial cleaning and room-servicing duties alongside code **37-2012.00**. It illustrates the actual description–code pairing available on the site. [SeasonalJobs.dol.gov](https://seasonaljobs.dol.gov/jobs/H-400-25216-217864?utm_source=chatgpt.com)

**Limitations:** Coverage is seasonal nonagricultural employment. Also, DOL recognizes jobs combining duties from multiple occupations, so a single published code should be interpreted with the full application and determination context. [dol.gov](https://www.dol.gov/sites/dolgov/files/WHD/fab/2022-3.pdf?utm_source=chatgpt.com)

### B. DOL SeasonalJobs: H-2A agricultural clearance orders

**Assessment: Another strong source, with especially explicit instructions identifying who enters the code.**

**Access:** The same [SeasonalJobs feeds](https://seasonaljobs.dol.gov/feeds), particularly the ETA-790/790A job-order feed.

**Who enters the mapping?** The ETA-790/790A instructions linked from DOL’s official forms page designate the clearance-order section for the **State Workforce Agency only**. Within that section, the SWA is instructed to enter the SOC code that best describes the agricultural work identified in the employer’s form. [U.S. Department of Labor](https://www.dol.gov/agencies/eta/foreign-labor/forms?utm_source=chatgpt.com)

The [job-order feed dictionary](https://api.seasonaljobs.dol.gov/sites/default/files/2023-08/JOMapping.xlsx) includes `jobDuties`, `socCode`, `socTitle`, `clearanceOrderNumber`, and **`issueDate`**, together with the employment dates.

**Which SOC edition?** DOL says that clearance orders issued **after July 1, 2022**, receive SOC 2018 codes. Previously issued orders with SOC 2010 remained valid for linking to applications. The relevant date is therefore the **clearance-order issue date**, rather than a later application or webpage date. [flag.dol.gov](https://flag.dol.gov/index.php/node/23042?utm_source=chatgpt.com)

**How I would use it:** Retain the employer’s duties, the SWA-entered code, the clearance-order identifier and issue date, and the applicable form version. Preserve multiple-employer, worksite, or activity information where present.

### A shared access limitation for both SeasonalJobs sources

The official JSON feeds update daily and cover records submitted, accepted, or updated within the **preceding 20 days**, depending on the feed. They are useful for ongoing collection, but they are not a complete historical bulk archive. [SeasonalJobs.dol.gov](https://seasonaljobs.dol.gov/feeds?utm_source=chatgpt.com)

The regular [OFLC public disclosure files](https://www.dol.gov/agencies/eta/foreign-labor/performance) can help identify applications and determinations. However, DOL warns that large text fields, including job duties, can be omitted. I would not treat those disclosure files alone as a full description–SOC corpus. [U.S. Department of Labor](https://www.dol.gov/agencies/eta/foreign-labor/performance?utm_source=chatgpt.com)

## 3. Sources worth requesting from the responsible agency

These have relevant human reporting or coding processes, but I did **not** verify a publicly downloadable corpus containing all the necessary paired text, codes, and provenance.

### A. O*NET Occupational Code Assignment case records

**Why this is promising:** The [O*NET Occupational Code Assignment service](https://www.onetcenter.org/coding.html) accepts a **Part A** form containing occupational information. An occupational analyst reviews it and returns **Part B**, which lists and explains the assigned code. This is a particularly direct description-to-code adjudication process.

The site identifies the current system as based on SOC 2018 and says submitted information is treated as public information. However, I did not locate a public bulk archive of the paired forms. [onetcenter.org](https://www.onetcenter.org/coding.html?utm_source=chatgpt.com)

**What to request:** Existing, paired Part A and Part B records, including the job summary, duties, assigned code, explanation, assignment date, and exact O*NET-SOC taxonomy edition. Historical cases must be versioned individually.

**Status:** A strong acquisition lead; historical availability and release scope remain unconfirmed.

### B. Full ETA-9141 prevailing-wage application and determination records

These could extend occupation coverage beyond the seasonal jobs on SeasonalJobs. The useful unit would be the **full employer duty description paired with DOL’s issued classification**, while keeping any employer-suggested code separate.

DOL has stated that documents submitted to the NPWC are available through FOIA. That supports a records-request route, but does not establish unrestricted bulk availability or guarantee that every requested field will be released. [dol.gov](https://www.dol.gov/sites/dolgov/files/ETA/oflc/pdfs/national-prevailing-wage-center-updates.pdf?utm_source=chatgpt.com)

**What to request:** Full duty text, employer-suggested SOC, DOL-issued SOC, determination and redetermination dates, case identifiers, and the classification edition. The published disclosure extracts can support identification, but may omit the description itself. [U.S. Department of Labor](https://www.dol.gov/agencies/eta/foreign-labor/performance?utm_source=chatgpt.com)

### C. QCEW / Annual Refiling Survey records for NAICS

BLS documents an industry-coding process involving employer business-activity information and trained state coders. However, it also documents **system assignment for some nonrespondents**, so the full source cannot be presumed manually coded. [bls.gov](https://www.bls.gov/opub/hom/cew/data.htm?utm_source=chatgpt.com)

This is worth pursuing through the relevant state agency or [BLS restricted-data access program](https://www.bls.gov/rda/), specifically for response-linked, manually coded records. You would need confirmation that original activity narratives, coding-method indicators, and native NAICS editions are retained and accessible. [bls.gov](https://www.bls.gov/rda/?utm_source=chatgpt.com)

### D. National Compensation Survey records for SOC

BLS describes trained field economists collecting job information through respondent interviews and documents, and classifying work using its duties. Identifiable establishment information is confidential. [bls.gov](https://www.bls.gov/opub/hom/ncs/data.htm?utm_source=chatgpt.com)

This is another potential source of knowledgeable human coding. Before treating it as an obtainable dataset, confirm access to the original descriptions, the record-level coding process, and the edition used at collection. A published statistical product’s later transition to SOC 2018 would not, by itself, establish every underlying record’s original edition.

## 4. Official descriptions of classification categories

If by “descriptions” you also mean **the official descriptions of industries or occupations**, these are the most straightforward version-controlled sources. Their unit is the classification category, rather than a particular establishment or job.

| Source | What it provides | Edition handling |
|---|---|---|
| [Census NAICS manuals and reference files](https://www.census.gov/naics/) | Official industry definitions, inclusions, exclusions, and index entries mapped to NAICS | Download the explicitly labeled **2017** or **2022** materials. [census.gov](https://www.census.gov/naics/?utm_source=chatgpt.com) |
| [BLS 2018 SOC definitions](https://www.bls.gov/soc/2018/home.htm) | Official occupation descriptions mapped to six-digit SOC codes; definitions available in spreadsheet and PDF formats | Explicitly **SOC 2018**. The Direct Match Title File is also useful, but supplies titles rather than full job descriptions. [bls.gov](https://www.bls.gov/soc/2018/home.htm?utm_source=chatgpt.com) |
| [O*NET database](https://www.onetcenter.org/database.html) and [archived releases](https://www.onetcenter.org/db_releases.html) | Occupation descriptions, task statements, and reported titles | Preserve both the database release and taxonomy edition. **O*NET-SOC 2019 is aligned to SOC 2018**; database release **25.1** was the first using that taxonomy. [onetcenter.org](https://www.onetcenter.org/database.html?utm_source=chatgpt.com) |

**O*NET needs an additional provenance check under your no-modeling requirement.** Its taxonomy-development documentation describes analyst work on occupational descriptions, but the current overall data-collection program explicitly includes AI/SME methods, machine learning, and natural-language processing alongside incumbents, experts, and analysts. I would therefore evaluate the particular file, field, and release instead of labeling the entire current O*NET database as human-generated. [onetcenter.org](https://www.onetcenter.org/dl_files/TaxonomyDev2019.pdf?utm_source=chatgpt.com)

For task statements, O*NET provides source and date metadata. The documented date is an update date, so it should not automatically be interpreted as the date a worker originally reported the task. [onetcenter.org](https://www.onetcenter.org/dictionary/31.0/excel/task_statements.html?utm_source=chatgpt.com)

## 5. Sources and shortcuts I would exclude from an unqualified human-coded set

- **The full OSHA SOC column.** OSHA generally assigns occupation codes using NIOCCS autocoding. Some cases receive review, and manually reassigned codes have identifying flags, but those would need to be treated as a separate, explicitly documented subset. OSHA’s employer-reported NAICS field and its autocoded SOC field have different provenance. [osha.gov](https://www.osha.gov/sites/default/files/ITA_data_users_guide.pdf?utm_source=chatgpt.com)
- **Unfiltered Census survey occupation or industry codes.** Census documents a mixture of automated and clerical coding. Its published classification lists also need to be distinguished from native NAICS and SOC codes. [census.gov](https://www.census.gov/topics/employment/industry-occupation/about/industry.html?utm_source=chatgpt.com)
- **Automatically crosswalked codes presented as original labels.** A human-entered NAICS 2017 code converted to NAICS 2022 is a derived 2022 label. Preserve the original code and edition; record any conversion separately.
- **A current webpage timestamp used as the classification vintage.** It can establish when a profile was updated without establishing when, or under which edition, its code was assigned.

## Recommended starting selection

For **actual establishment descriptions**, I would start with **OSHA ITA**, accepting only records with sufficient descriptive content and defensible edition metadata. I would add **reported TRI records** where the facility narrative is suitable. OMWBE and SBA are useful supplements when business-level capability descriptions are acceptable.

For **actual job descriptions**, I would start with **SeasonalJobs H-2B and H-2A records**, preserving the linked determination or clearance-order dates. For a broader, potentially more carefully adjudicated occupation corpus, the strongest request targets are **O*NET OCA paired case files** and **full ETA-9141 records**.

For every accepted pair, I would retain:

| Metadata | Why it matters |
|---|---|
| Original description and unit type | Distinguishes an establishment, firm, job, process, or taxonomy category |
| Original code and exact classification edition | Establishes the label actually supplied or assigned |
| Reporting/coding role and method | Supports the human-provenance requirement |
| Assignment or determination date | Establishes when the classification decision occurred |
| Observation, employment, or reporting period | Establishes what period the description concerns |
| Source identifier, form version, and release date | Makes the pairing auditable |

That approach preserves the two properties you specified—**knowledgeable human assignment and known classification timing**—without silently replacing either with a later inferred value.
